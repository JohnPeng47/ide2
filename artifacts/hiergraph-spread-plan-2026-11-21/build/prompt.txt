<task>
Model

- HierGraph = (V, T, E)
  - V is a finite set of nodes.
  - T is a set of ordered pairs from V x V. The graph (V, T) is directed and acyclic.
  - E is also a set of ordered pairs from V x V. Its relations may form cycles.
  - Vertical (compositional). (whole, part) in T means part is a direct part of whole. Following T downward moves from a whole into its parts. A shared part can have several parents and retain one identity.
  - Horizontal (relational). (u, v) in E records a relation from u to v. Its meaning comes from the particular graph. The endpoints can occur at different vertical levels.
  - A root has no incoming T edge. A leaf has no outgoing T edge. Multiple roots, shared descendants, disconnected components, and isolated nodes are all valid.

Task

Build the complete set of canvases specified by the spread plan, as one linked canvas set. The plan is the specification: build every canvas, every diagram and every link it lists, with the IDs it gives. Do not add canvases or diagrams the plan does not list, and do not drop any it does list.

The plan says what each diagram covers. You write its content: an ASCII tree whose nodes are the real components, fields, operations and relations found in the source. Each diagram's first line is its title. Go as deep as the plan's description asks; read the cited files to get names, ownership and relations right.

The plan's link lists name endpoints as `Canvas/diagram → node`. Create a line for every named endpoint so the link has somewhere to attach. When the source contradicts a planned link or node, follow the source and note the change in the explanation.
</task>

<canvas-style>
<canvas-guidelines>
Edges. Draw an edge only between two different diagrams on the same canvas, for the links the plan lists between them. Never draw an edge whose source and target are in the same diagram: within one diagram, nesting and annotated relation lines already carry T and E.

Jumps. Use few, deliberate jumps: 2–3 out of each canvas on average, about 20–25 across the whole set. Spend them first on entrances, one from each anchor node to the child or same-level canvas it opens, then on the few cross-canvas relations that matter most for following the system's main paths. Every other cross-canvas link in the plan stays an annotated relation line naming its target canvas, diagram and node, without a jump. Compute each jump's startColumn and endColumn from the exact final text of its line, for example with a short script, so the span covers the whole target name and no partial words; do not count columns by hand.

Positioning. Before placing a canvas's diagrams, decide how they relate spatially:
- Center: the diagram the canvas is about, usually the one its entrance points to (for example the core overview, or the composition diagram of a child canvas).
- Beside the center: diagrams that directly elaborate or compose parts of the center diagram. Place each one close to the part it elaborates.
- Periphery: diagrams related more loosely, such as horizontal traces that cross several parts, or optional subsystems.
Arrange the diagrams in two dimensions around the center, not in a single row or column. The center diagram sits in the middle of the arrangement, with the other diagrams placed on more than one of its sides, not all to its right or all below it.

Spacing. Keep the gap between each diagram and its nearest neighbour roughly the same across the canvas, so that no diagram is isolated in a corner. Diagrams must not overlap: a diagram's width is its longest line and its height is its line count.
</canvas-guidelines>
