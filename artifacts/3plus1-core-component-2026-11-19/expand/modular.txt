<task>
You are given a canvas of diagrams representing the core component of the codebase: the connected set of responsibilities around which the application's main behavior and state are organized.

Your task is to restructure this canvas in place. Choose which diagrams to expand; restructure each chosen diagram into a central diagram with a couple of peripheral diagrams connected to it. Return the complete canvas, including the diagrams you leave unchanged.

Framing

A tree diagram can relate components in two ways:

- Vertical (modular): depth means "belongs to". A child is a submodule, type or function grouped within its parent's responsibility. Reading down a branch, you move from a module into the pieces it groups, and from what it exposes into what it keeps internal.
- Horizontal (relational): modules that depend on one another without one belonging to the other, e.g. a module using another's exposed interface, or a shared utility used by several modules.

A diagram is *flat* when its modules sit side by side as top-level peers, even when one actually belongs inside another, and the dependencies between them appear only as inline references. This hides how the system is organized.

Before:

  Podcast player
  |
  |-- library: shows, episodes, subscriptions
  |-- library/search: query parsing and index lookup
  |-- playback: public play / pause / seek API
  |-- playback/queue: ordered episode list
  |-- audio: decoder and output device wrappers
  |-- downloads: fetch and cache episode files
  `-- sync: progress upload; uses playback and library

After:

  Podcast player
  |
  |-- Library
  |   |-- Exposes: shows, episodes, subscribe()
  |   `-- Internal: Search
  |       |-- query parsing
  |       `-- index lookup
  |-- Playback

  |   |-- Internal: Queue (ordered episode references)
  |   `-- -> depends on Audio.load / start and Downloads.cachedFile
  |-- Audio (shared; exposes load / start / stop)
  |-- Downloads

  `-- Sync
      |-- -> depends on Playback position events

1. Choose which diagrams to expand
   - If the canvas holds a single diagram, expand it.
   - Otherwise, prefer to expand along the vertical dimension: choose diagrams with nodes that hide modular structure of their own, i.e. modules that group submodules, and pull that structure out downward into new diagrams.
   - Avoid expanding sideways: do not add new peer topics that are only horizontally related to what the canvas already shows.
   - Leave a diagram unchanged when it is already small and focused; not every diagram needs expanding.

2. Restructure each chosen diagram into a central diagram
   - Give it a primarily *vertical*, modular structure: nest each component under the module it belongs to, so the shape of the tree alone shows how the system is organized and what each module exposes or keeps internal.
   - Do not discard the horizontal relationships. Some components will not nest cleanly (e.g. a shared utility used by many modules, or an interface consumed across a boundary). Do not force these under a false parent; instead, express the relation as an annotated dependency line under the specific module or interface that depends on it.
   - The vertical structure is the skeleton; horizontal relations are laid over it.

3. Pull out concepts that should become their own diagrams
   - Each peripheral diagram should connect to the node in the central diagram, at the depth, that it elaborates.
   - Where a horizontal relation in the central diagram links two pulled-out concepts, connect those peripheral diagrams to each other as well.
   - A peripheral diagram goes deeper into its central diagram's scope; it does not widen that scope or repeat what another diagram on the canvas already covers.

4. Preserve the rest of the canvas
   - Keep the IDs of existing diagrams, including the ones you expand, so their existing edges stay attached. Return unchanged diagrams with their ASCII exactly as given.
   - Keep every existing edge. Re-point an edge only when restructuring moved or removed the line it pointed to.
   - Place new diagrams next to the diagram they expand. Existing diagrams may shift only to make room.
