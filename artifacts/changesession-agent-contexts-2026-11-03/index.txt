Usage
Select a saved context in the AgentContext library/Evals. Its complete visible prompt is in XX/prompt-v1.txt and included verbatim in the immutable context. It specifies owned parents, read-only context, source inputs and generation constraints. No model run or ChangeSession acceptance was performed when creating this input set.

The eval output remains the prior requested format: modified existing diagrams plus high-level missing-detail specifications and an ASCII recap. New missing diagrams are not generated. No expected-answer ASCII is included.

Validation
ownership.json: complete partition of all 16 canvases; six already-current/library canvases are read-only.
validation.json: 12 feature areas covered, 8 missing-detail proposals assigned once, 3 migrations with colocated endpoints, all original diagram ASCII preserved as captured input.
saved-context-verification.json: server readback, immutable hashes, every source pin and resolved text checked against exact Git objects.
manifest.json: saved IDs, hashes and input provenance.
inputs/live-reads.json: complete captured source evidence and short API handles, which must be refreshed before use.
XX/code-diff.patch: full path-scoped source diff; the saved context itself includes target files and before excerpts/changed line ranges.

Known integration limit
The entire repository range includes unrelated investigation dumps and exceeds get_repository_diff_hunks' 8 MiB cap. These contexts retain the relevant code change evidence without fabricating server hunk IDs. Full-range DiffTree generation needs narrower supported capture or an API improvement; plain isolated proposals can still use the supplied evidence.

Reproduction
build.py regenerates requests from the frozen inputs and pinned Git objects. It preserves request UUIDs; do not change a request payload and retry its old UUID. save-and-verify.mjs submits the exact saved request files through MCP and verifies their persisted snapshots. No application source files were edited.
